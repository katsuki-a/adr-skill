# 検証するADRプロファイル

Python 3.9以上。CLIは標準ライブラリのみを使用する。対象はこのskillの [テンプレート](../assets/adr.md) から作ったUTF-8 Markdown。

構成は[Nygard](https://www.cognitect.com/blog/2011/11/15/documenting-architecture-decisions)、メタデータの配置は[MADRの設計判断](https://adr.github.io/madr/decisions/0013-use-yaml-front-matter-for-meta-data.html)を参考にしている。以下の見出し・メタデータ・期限の規約はこのツール独自のもので、ADR一般の標準やMADR完全互換ではない。

## 形式

- 識別子は `ADR-001`、ファイル名は `ADR-001-slug.md`、タイトルは `# ADR-001: 題名` で番号を一致させる。番号は1から始まる正整数を最低3桁にゼロ埋めし、999の次はADR-1000。ADR-000や余分なゼロ埋めは認めない。slugは英小文字・数字をハイフンで区切る。検査対象内の同じディレクトリでは番号の重複を認めない。
- H1は1つ。本文のH2は `Context` → `Decision` → `Consequences` の3つだけ、順序も固定。フロントマターの後からタイトルまでと、タイトルからContextまでの間は空白だけ。
- 新規テンプレートのContextには `### Problem to Solve` と `### Considered Options and Trade-offs` を置く。課題・判断軸と選択肢ごとの比較を分け、Decisionには選択と理由、Consequencesには採用後の影響を記す。このH3構成は作成時の案内であり、既存ADRの必須検証項目にはしない。
- 本文の各節は空にせず、テンプレートの `{{problem}}`・`{{options}}` 等は埋める。HTMLコメントや小見出しだけの節もエラー。
- メタデータはファイル先頭の `---` と次の独立行 `---` の間に置く。必須キーは `status` と `proposed-on`、任意キーは `superseded-by`。本文にStatus節を併記しない。
- 本文には日本語等の任意の言語、箇条書き、表、リンク、H3〜H6、バッククォート/チルダのコードフェンス、HTMLコメントを使える。構造見出しは行頭からのATX形式に限る。Setext見出し、コメント以外のHTMLブロックは対象外。コードフェンス・コメントは閉じる。
- 見出し行上のコメントは整形による欠落を防ぐため拒否する。コメントは本文の独立行に置く。汎用Markdown/HTMLパーサではなく、上記の限定された形式を検査する。

## フロントマターの限定構文

```yaml
---
status: Proposed
proposed-on: "2026-09-13"
---
```

キーは小文字・行頭開始、コロンの後に空白を置く。順序は任意で、formatterが `status` → `proposed-on` → `superseded-by` に統一する。値は英数字、ピリオド、スラッシュ、ハイフン、アンダースコアと語間の半角空白からなる単純な文字列。引用符なし・一重引用符・二重引用符を受け付け、引用符内のエスケープは認めない。各キーの意味上の制約（日付、状態、ファイル名）は別に検証する。

整形後は日付を二重引用符で囲み、状態と置換先は引用符なしにする。汎用YAMLローダーによる日付の型推論を避けるため、日付は文字列として出力する。未知キー、重複キー、空値、コメント、配列、ネスト、複数行値、タグ、アンカー・エイリアスは拒否し、内容を黙って削除しない。空行は許容し、整形時に取り除く。汎用YAMLパーサではない。

旧 `## Status` 形式は `E_FRONTMATTER` で失敗し、自動変換しない。既存文書の移行では、Status節の値を対応する小文字キーに移し、日付を維持して旧節を削除する。外部文書は明示的な移行対象だけを変更する。

## ステータス

| 値（大小文字を区別） | 意味 | メタデータ上の制約 |
| --- | --- | --- |
| Proposed | 提案中、合意前 | 提案開始日からの期限検査対象 |
| Accepted | 関係者が合意済み | 提案開始日は残す |
| Rejected | 提案が不採用 | 提案開始日は残す |
| Deprecated | 過去に採用したが現在は非推奨 | 提案開始日は残す |
| Superseded | 別ADRに置き換えられた | superseded-byに同じディレクトリの別の実在ADRファイルを指定 |

通常はProposedからAcceptedまたはRejectedへ、AcceptedからDeprecatedまたはSupersededへ変更する。CLIは現在の値・付随フィールドを検査する。Git上の遷移履歴、実際の合意、置換先の本文・状態、置換の循環までは判定しない。

`proposed-on` は提案を始めた実在の日付。全状態で必須・未来日不可。最終編集日でもファイルのmtimeでもない。再提案は別ADRとして記録する。Git履歴を参照しないため、日付の改ざんや誤記は機械的には検出できない。

期限は `(評価日 - proposed-on).days >= N` のときエラー。既定N=30暦日、変更は `--max-proposed-days N`（正整数）。29日は成功、30日は失敗。評価日は実行環境のローカル日付、再現用に `--today YYYY-MM-DD` で固定できる。編集・整形で時計をリセットしない。CIのタイムゾーンを運用と揃える。

## CLI

以下の `<tool>` はskill内の `scripts/adr.py`。

```sh
python3 <tool> new --directory docs/adr --slug use-sqlite --title 'SQLiteを採用する'
python3 <tool> format docs/adr/ADR-001-use-sqlite.md
python3 <tool> lint docs/adr
python3 <tool> format docs/adr --check
python3 <tool> index docs/adr
python3 <tool> index docs/adr --check
python3 <tool> lint docs/adr --max-proposed-days 14 --today 2026-09-13
```

`new` はファイル名から次の番号を採番し、雛形のパスと内容を出力する。既存ファイルは上書きしない。本文の未記入部分はlintに通らない。採番は直下だけを対象とするため、同一ディレクトリでのnewは直列に実行する。削除済み番号をGit履歴から復元しないため、過去ADRは削除しない。

`lint` は書き込みなし。`format` は各ファイルを検証し、意味上のエラーがないファイルの構造見出し・フロントマターの書式・節境界の空行とLF改行だけを正規化してlintも完了する。本文中の空白、ハード改行、リスト、コードはLF化以外を保持する。状態、日付、文章、欠けた節、未知の状態を推測して修復しない。滞留中のADR本文も自動変更しない。

複数ファイルでは、エラーのないファイルだけ整形される場合がある（バッチ全体のトランザクションではない）。lint/formatは別の編集処理と同時に実行しない。READMEの更新と `--check` の範囲は[README一覧](#readme一覧)を参照。

ディレクトリ指定は配下の `*.md` を再帰検査し、README.mdと隠しパスを除く。明示ファイルは除外しない。不正な名前の.mdも検出し、シンボリックリンクのADRファイルは拒否する。指定範囲外の重複番号等は検査しない。空ディレクトリは成功扱いにしない。

正常時は集計1行。異常時は既定20件まで表示するが検査は全件を完走する。`--max-errors N` で表示上限を変更できる。終了コードは0=成功、1=対象ファイルの違反・読取失敗・一覧の更新漏れ、2=引数不正・対象なし・生成失敗・index処理失敗など。

毎回全対象を読むが、ファイル単位の処理は本文サイズに対して線形。lintは変更ファイルだけ渡せる。自動通知・定期実行は含めず、CI等から全件lintを定期実行すれば、編集のないProposedも検出できる。

## README一覧

一覧は各ディレクトリ直下のADRを番号順に並べた `README.md`。サブディレクトリには別の一覧を置く。

| 操作 | 一覧への作用 |
| --- | --- |
| `new` | 新規ADRを含めて保存先の一覧を更新する |
| `format <対象>` | 指定ADRのある各ディレクトリの一覧を更新する。ADRが整形済みでも更新する |
| `index <directory>` | 指定ディレクトリの一覧を更新する。引数省略時は `docs/adr`。CLI外でのメタデータ編集・改名・削除後にも使う |
| `index <directory> --check` | 一覧の欠落・差分を検査する |
| `format <対象> --check` | ADRの検証・整形状態に加え、各対象ディレクトリの一覧の欠落・差分を検査する |
| `lint <対象>` | ADRだけを検証し、一覧は検査・更新しない |

`--check` は書き込まず、一覧の欠落・差分があれば終了コード1。CIでは `format docs/adr --check`、または `lint docs/adr` と `index docs/adr --check` を使う。

列はID（ADRファイルへのリンク）、Title、Status、Proposed on、Superseded by（置換先へのリンク）。READMEの `<!-- adr-index:start -->` と `<!-- adr-index:end -->` の間だけを更新する。READMEがなければ作成し、領域がなければ末尾に追加する。領域の外の手書き内容はバイト単位で保持する。行の追加・更新・削除・並び替えは自動生成するため、表を手で編集しない。

最後のADRを削除した空ディレクトリではindexが空表を生成できるが、lint/formatは対象なしで失敗する。

一覧生成は同じディレクトリの各ADRのメタデータとタイトルを読み、本文は解析しない。formatで本文の検証に失敗しても、読み取れるメタデータを反映して一覧が更新される場合がある。新規の未記入本文も一覧に載るが、ADR自体のlintには引き続き失敗する。滞留中のProposedも一覧から消さない。日付・状態・IDの形式、重複番号、置換先は検証する。不正なADRヘッダーは黙って除外せず処理を失敗させる。評価日の再現にはindexにも `--today YYYY-MM-DD` を指定できる。

一覧が同一ならREADMEを書き直さない。更新は一時ファイルから置換し、書込み失敗による途中の表を残さない。壊れた管理マーカー・シンボリックリンク・README以外の大小文字表記は自動修復しない。newは生成前に既存一覧を検査するが、ADR作成後のREADME書込み失敗ではADRは残るので、エラー解消後にindexを再実行する。ADRとREADMEをまとめたトランザクションや同時実行のロックは提供しない。
